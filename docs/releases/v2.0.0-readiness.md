## F. Tag 自动发布更新（2026-10-21）

发布机制已改为 [CI_RELEASE_WORKFLOW.md](CI_RELEASE_WORKFLOW.md) 中的六 Job Tag 自动流程。前述 RC4 数据与本地命令表是历史准备证据，不能代替新 CI 结果。旧 candidate 入口现在仅检查静态策略；完整 dry-run 使用 `release.yml` 的 workflow_dispatch，无发布权限。正式发布由合法 Tag push 触发，RC 创建 Pre-release，正式 Tag 创建正式 Release；不再要求手工创建 Release 或上传本地包。

源码版本由 VERSION 和 CLI 默认版本交叉校验；实际 RC 版本通过链接参数写入 CLI/LSP。M18 仍复用正式脚本并额外核对 golden、GC=1 和 Shadow Frame=0。失败不降级；仅本次 run/attempt 的验证资产可进入 Publish，同名 Release 一律停止。签名仍为 ad-hoc，无 Developer ID 和 notarization。

Readiness 继续为 **CONDITIONAL**：本地自动化验证结果记录在 `build/release-automation-audit/`，首次 hosted dry-run 和真实 Tag CI 未执行，不能宣称通过。当前 public 仓库 Actions 已启用；实际 runner 调度、资源、LLDB 权限、发布 Token 权限和 Gatekeeper 体验待远端/真实安装验证。完整审查和提交所有现有修改仍是发布前置条件。

本次自动化实施没有 Commit、Push、Tag、远端 workflow dispatch、创建/更新 GitHub Release、上传真实发行资产、修改远端设置、hard reset、git clean 或删除既有证据。
