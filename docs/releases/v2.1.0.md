# Mio v2.1.0 release notes

**Draft.** v2.1.0 has three native release targets. Stable acceptance is pending.

| Target | Format | Downloads |
| --- | --- | --- |
| macOS ARM64 | Mach-O | Core and Full archives |
| Linux AMD64 | Static ELF | Core and Full archives, offline Docker archive for Full |
| Windows AMD64 | PE32+ | Core and Full ZIPs and per-user installers |

Core and Full ship byte-identical compilers for each target. Full includes the
external Bunko standard library, release examples and the integrated
`check`, `build`, `run`, `exec`, `test`, `lsp` and `disasm` commands. Core can
build programs without library imports and can use an external Bunko tree.
Neither package requires Go, Python or a development toolchain.

Keep the Full directory tree together when moving an installation. The
compiler looks for Bunko in this order: `--bunko-root`, `MIO_BUNKO`, then
`../bunko` relative to the executable. Invalid explicit roots produce an error.
On Windows the Core installer exposes `mio-core` and the Full installer
exposes `mio`.

## Changes since v2.0.0

- Native AOT now targets Linux and Windows AMD64 alongside macOS ARM64. The
  Go reference frontend and VM remain available for development and comparison.
- [Runtime ABI RA-1](../runtime-abi.md) specifies shared language semantics and
  memory safety across native targets. Darwin uses generational collection and
  the x86-64 targets use precise mark-and-sweep. All three expose `--gc-stress`.
- Windows supports blocking IPv4 `kiso/net/tcp` via Winsock, including the TCP
  package and client/server echo examples. The API uses IPv4 literals and
  blocking sockets.
- The native CLI emits Mochi bytecode for the existing Web VM. CI compares
  native-CLI-produced Mochi and the reference VM, then exercises the playground
  in Chromium.
- Darwin native programs now require explicit `chant` output for the last
  top-level expression. For floating-point output on Linux and Windows, use
  `convert.format_float64/32` before calling `chant`. macOS packages use ad-hoc
  signing. Concurrent Old-GC is disabled by default.

| Exact stable artifacts, trusted bootstrap, and signed stable verification | **NOT_RUN**. Requires the tagged stable build on a GitHub-hosted Darwin ARM64 runner using the [pinned immutable GF4 seed](https://github.com/mio-kobo/mio/releases/tag/gf4-seed-v1-immutable). |

The stable workflow builds from the exact tagged source and stamps its commit
and version before compilation. The frozen Darwin ARM64 GF4 executable starts
an independent native build. Its Darwin B/C/D fixed point and matching Linux
and Windows cross builds must produce the same bytes as the compilers tested
natively on each target. The signed release verification report binds the
result, compiler hashes, package contents, installers and offline Docker
checks to the tag and source commit. See the [verification instructions](../testing.md#stable-distribution-and-trusted-gf4)
and [installation guide](../installation/README.md) for details.
