# Mio v2.1.0-rc.1

This is a pre-release for testing before v2.1.0, not the stable release. macOS
ARM64 is the primary target; Linux AMD64 and Windows AMD64 remain experimental.

## Choose a download

Choose the archive for your operating system and architecture. **Full** is the
recommended download: it includes Bunko and examples. **Core** contains the same
compiler without the importable standard library. Go and Python are not needed
to use either package. Windows also has per-user Core and Full setup executables;
Core's installer exposes `mio-core`, while Full exposes `mio`.

Verify the download against `SHA256SUMS` before unpacking or installing. For
archives, put the extracted `bin` directory on PATH and keep the Full directory
tree together. Do not copy only the compiler out of Full.

```sh
mio version
mio check examples/math.mio
mio build examples/hello.mio -o hello
./hello
```

On Windows, run `hello.exe`. Core requires `--bunko-root <directory>` or
`MIO_BUNKO` for `kiso/` imports. An invalid explicit root fails rather than silently
using a different library. Full normally discovers its own adjacent Bunko.

RC1 is distributed through GitHub Releases. Stable Homebrew, APT, WinGet and
Chocolatey publication is not activated by this pre-release.

## Changes since 2.0

- Pure Mio compiler, runtime and native backends for Darwin ARM64, Linux AMD64
  and Windows AMD64; the Go AOT implementation has been removed. The Go reference
  frontend/VM remains a development oracle and bootstrap host.
- Runtime ABI RA-1, native self-hosting fixed points and native library tests on
  all three targets, with ABI and VM/native differential coverage.
- Core/Full packaging, external Bunko discovery, relocation checks, Windows
  process support, integrated `check/build/run/exec/test/lsp/disasm` tools and
  installation/upgrade/removal checks using real package managers.
- Shared nullable type analysis and Linux/Windows runtime trap-message fixes;
  reduced Darwin memory-pressure query overhead.

**Compatibility change:** compiled Darwin programs no longer print the final
top-level expression automatically. Use explicit `chant` output.

## Known limits and verification boundary

- Linux/Windows cannot directly `chant` floating-point values. Use
  `convert.format_float64/32` to produce text.
- Windows `kiso/net/tcp` is unavailable because the Winsock layer is not
  implemented. It is recorded as NOT_APPLICABLE, not a passing test.
- macOS binaries use ad-hoc signing and are not Apple-notarized.
- Concurrent Old-GC is not enabled by default. RC1 does not claim concurrent or
  multi-mutator GC support.
- Two allocation-heavy differential cases are excluded from per-allocation GC
  stress because that configuration is quadratic; their normal-mode checks run.
- Hosted native verification starts from a Go-hosted Stage A and checks native
  B=C=D. Trusted GF4 Seed validation is a separate requirement for stable
  distribution. Hosted reports retain their actual Seed NOT_RUN status; a green
  hosted result does not satisfy that stable release requirement.

Release assets include source-bound native reports, extracted-package checks,
manager lifecycle evidence, Docker offline evidence and checksums. The published
release description identifies the exact verification run and any remaining
stable-release blocker. PR archives are never renamed into release candidates.

The root `VERSION`, legacy CLI template and `tools/native-ci` source pins remain
the frozen 2.0 bootstrap inputs. The distribution preparer stamps RC1's version
and full source SHA into a disposable source tree **before** native compilation;
the shipped binary, manifest and provenance must agree.
