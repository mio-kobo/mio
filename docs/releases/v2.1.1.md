# Mio v2.1.1 release notes

**Unreleased.** v2.1.1 is a focused maintenance release for the native compiler
distribution. It does not change Mio language syntax, Mochi format semantics,
Native AOT output requirements, Bunko public APIs, or the packaging of
user-compiled programs.

| Target | Format | Archives |
| --- | --- | --- |
| macOS ARM64 | Mach-O | Core and Full |
| Linux AMD64 | Static ELF | Core and Full |
| Windows AMD64 | PE32+ | Core and Full ZIPs and per-user installers |

## Core and Full

- **Full** is one self-contained native `mio` executable (`mio.exe` on Windows)
  with the complete Bunko standard library embedded. It has no external `bunko/`
  directory, needs no network access, and supports `kiso/...` imports as soon as
  it is installed. Copying only the executable to a compatible computer keeps it
  usable.
- **Core** is a smaller compiler with an empty embedded table. It compiles
  library-free programs and can use an external Bunko tree exactly as v2.1.0 did.
- The embedded table contains all production `kiso/` sources and their transitive
  dependencies, excluding tests and historical dotted snapshot directories. It is
  generated by the Mio-native `selfhost/resourcegen` path at build time.
- Full and Core are built through separate native fixed-point chains. Their
  binaries intentionally have different SHA-256 hashes.

## Bunko resolution

1. `--bunko-root <directory>` (nonempty and must contain `kiso/`).
2. `MIO_BUNKO` (an existing empty value is an error).
3. Embedded Bunko (Full only).
4. `../bunko` relative to the real executable (Core and legacy layouts).
5. No library; `kiso/...` imports report `E_BUNKO_MISSING`.

Invalid explicit or environment roots fail without falling back. Full therefore
uses its embedded library by default but still accepts explicit external
overrides for development or a different library.

## Verification

Native CI builds Full and Core on macOS ARM64, Linux AMD64 and Windows AMD64,
requires both B=C=D fixed points, and runs embedded imports, transitive imports,
Core's missing-Bunko diagnostic, explicit/environment overrides, invalid-root
precedence and invalid-module checks. Package verification relocates the actual
archives, copies the Full executable alone into a clean directory, and compiles
and executes programs importing `kiso/math`, `string`, `array`, `bytes`, `io`,
`fs`, `encoding/json`, `regexp`, `crypto/sha256`, `os` and `net/tcp`.

No archive is published by this document. Do not create a v2.1.1 tag or Release
until the maintainer approves the release workflow and evidence.
