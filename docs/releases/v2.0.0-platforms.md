# Mio 2.0.0 平台、依赖与已知限制

## 平台承诺

| 范围 | 本次结论 |
| --- | --- |
| macOS Apple Silicon / ARM64 | 唯一候选发行目标；macOS 15.6 实机执行、结构、签名、安装 smoke |
| 更早 macOS / 其他 Apple Silicon 系统版本 | 未建立最低支持版本，未验证 |
| Intel Mac、Linux、Windows | 无 V2 正式支持认证，不生成正式支持候选包 |
| 容器、无 sandbox-exec / LLDB 的环境 | 不保证完整 M18 验收可运行 |

## Go 与系统工具

| 操作 | Go 工具链 | 实际实现 / 其他需求 |
| --- | --- | --- |
| 解压安装及 mio version/help | 不需要 | tar、shell；候选二进制内含 Go runtime |
| mio check/run/build/exec/disasm/test/lsp | 不需要 | 预编译 Go 前端 / VM / LSP；Bunko 在包内，设置 MIO_BUNKO |
| 发行包 mochi-aot | 不需要 | Go 实现的 AOT 后端已编入可执行文件；输出后需系统 codesign |
| 发行包 native-aot | 不需要 | 纯 Mio 原生编译器，Mochi 输入，config 文件路径协议，1 GiB managed arena；输出需 codesign |
| 生成的原生用户程序 | 不需要 | 独立原生 runtime / mmap arena / Darwin syscall；不需要 Go 或 VM |
| 源码重建工具、首次 Seed | 需要 | go.mod 基线 1.22.2，实测 1.25.9，CGO_ENABLED=0 |
| 正式 M18 + GC 见证 | 需要（构建前端与 Seed） | Python 3、Go、codesign、sandbox-exec、LLDB；Seed 后纯 Mio 生成且禁止 exec/fork |
| 本地打包与安装 smoke | 构建时需要，安装时不需要 | Python 3.12+（本次），Go、tarfile、codesign、file、otool；smoke 执行 PATH 为空 |

正式 M18 不是完整源码编译流程移除 Go 的声明。Go 源码前端编码共同自编译输入；Go AOT 正式链只生成 Seed。独立语义对照测试可以使用 Go AOT，不能将其结果冒充纯 Mio Stage 产物。

原生运行时为精确 Mark-Sweep，包含 Shadow Frame、nullable / closure / enum 位图、typed Storage、大对象、空闲块管理及 mmap arena；不包括分代 GC。VM 和 Native 支持范围不同：Native 没有完整 Map 路径、通用 CLI argv 和任意 MMA 宿主桥接，函数值也以既有可达性和类型分析范围为限。内存容量受配置硬限制；正式 1 GiB 与 256 MiB GC 见证均真实运行，历史 128 MiB OOM 不改变协议。

## 编辑器证据边界

本次从相邻源码仓库只读核查：

- `../mio-vscode/package.json`：独立版本 0.3.0，VS Code engine `^1.85.0`，配置 `mio.executablePath`，通过 `mio lsp` 和 CLI 集成。
- `../mio-jetbrains/build.gradle.kts`：独立版本 0.6.1，IntelliJ 2025.3.2 / sinceBuild 253；SDK、Bunko 配置和 CLI 诊断集成。
- 核心 `cmd/mio/lsp_test.go` 与 `internal/lsp` 回归覆盖协议；候选安装 smoke 额外验证 initialize / serverInfo 2.0.0 / shutdown。

未改动两个插件仓库、未打包插件、未运行 IDE 实机测试。这些源码证据并不构成“插件与 V2 全面兼容”的保证。用户应将插件 CLI/SDK 路径设为候选包中的 mio，Bunko 指向包内目录；人工发布前需确认插件发现、诊断、运行和升级路径。外部仓库的独立版本和历史语言版本说明不盲目替换成 2.0.0。

## 签名与许可

全部候选可执行文件均检查 ARM64 Mach-O、ad-hoc 签名与 strict verify。Go 工具的动态库信息由 otool 记录；纯 Mio 镜像以原生 syscall 运行，不能把 Go 工具的 libSystem 依赖误写为零依赖。当前无 Developer ID 签名或公证结果，不使用或保存私密凭据；维护者可选择有凭据的独立发行流程，重签名后必须重新打包、更新哈希并重做安装验证。
