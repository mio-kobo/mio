## Tag 自动发布流程（本次不执行远端操作）

标准流程、命令模板、权限与 Ruleset 配置见 [CI_RELEASE_WORKFLOW.md](CI_RELEASE_WORKFLOW.md)。维护者只审核/提交源码并推送 Tag，CI 负责构建、验证和上传；不手动上传本地 RC4。

1. 审核全部源码、已有用户修改、未跟踪 M18 文件、工作流和 Release Notes。
2. 创建完整 Release Commit 并推送；将 workflow 合入默认分支以启用手动入口。
3. 在审核提交执行 `release.yml` workflow_dispatch，输入 `v2.0.0-rc.5`；前五 Job 全部通过且 Publish 跳过。
4. 推送 `v2.0.0-rc.5`，观察六个 Job 完整重验和自动 Pre-release。
5. 从 Pre-release 下载 tar.gz、SHA256SUMS、release-provenance.json；核对 SHA、Tag/commit、run 和实际安装体验。
6. 审核最终说明和签名限制，全部满足后推送 `v2.0.0`。
7. CI 从正式 Tag 全量重新验收并自动创建正式 Release；下载重新验证。
